## Q1. Global "interactive book / web book" products: what the buyer gets, price, access, progress tracking, and whether they call themselves a "book"

### Takeaway
Selling access to a web platform with progress tracking under a book or textbook label is a mature model in two places. The first is higher-ed publishing: zyBooks, Pearson Revel/eTextbook, and McGraw Hill SmartBook all use access codes, and all include progress dashboards. The second is tech publishing: Manning liveBook and Leanpub's "Web" format. Indie creators such as Josh Comeau, Execute Program, and Educative sell the same kind of interactive web product, but they call it a "course", not a "book". The products that most explicitly call the web product a "book" and pair it with progress tracking are zyBooks and McGraw Hill SmartBook.

### Inferences
- The case that "a book = paid access to a web app with progress" already has strong precedent, but mostly in **B2B2C textbooks** (zyBooks, Pearson, McGraw Hill), where the vocabulary is "access code" and "eTextbook". Indie creators with fully interactive web products (Comeau, Execute Program) chose the word "course", probably because "course" supports higher prices ($235–$599) than "book".
- Access models cluster into three types:
  1. Account plus a one-time redeemable code (Pearson, zyBooks).
  2. Account created at checkout (Comeau, Manning, Leanpub).
  3. Subscription (Educative, Brilliant, Execute Program).

  None of the confirmed cases rely on a pure magic link without an account.
- Progress features range from bookmarks only (Manning, Leanpub) to full completion dashboards (zyBooks, SmartBook) to habit mechanics (Brilliant streaks, Execute Program daily caps). The last group is closest to a "study amount / completed lessons / chart" dashboard.

## Q2. Korean cases: 전자책/교재 plus web or app access, progress tracking, and purchase verification

### Takeaway
In Korea the "buy a book → get web/app study access" model is common among **English textbook publishers**: 쎄듀→쎄듀런, NE능률→클래스카드, 길벗 구매도서인증, and QR codes from 다락원 and NE능률. However, these give the web or app access as a **free extra with a paper book**; they don't sell a "전자책" that *is* the web app. Among indie platforms, 크몽 전자책 must be a PDF. The accepted workaround is a PDF that contains a **Notion template link** to duplicate. 위키독스 is the closest Korean example of a paid "전자책" that is read on the web. **No Korean indie product was found that is sold as a "전자책" but delivers a web app with a personal progress dashboard.** This looks like an open niche, but it also means there is no platform precedent to lean on.

- Korean publishers mostly verify purchases **with information printed in the paper book** (ISBN 부가기호, QR codes, coupon numbers). For a digital-only product sold on a marketplace, the equivalent would be a **unique purchase code delivered with the order**, or an access link inside the PDF.

- 위키독스 shows that Korean readers accept "a paid 전자책 that you read on the web", but no progress dashboard was found there.

## Q3. How access is handled and whether buyers like the progress-tracking part

### Takeaway
Access is almost always **account plus a code**: one-time redeemable codes (Pearson, zyBooks prepaid keys, 쎄듀런 coupons) or information printed in the book (길벗 ISBN 부가기호, QR codes). Progress features are a core selling point in institutional products (SmartBook reports, zyBooks completion rates, 클래스카드 reports) and for habit-driven apps (Brilliant streaks, Execute Program daily caps). Direct evidence that *self-study buyers of a "book"* value the dashboard was not found.

### Inferences
- For a small creator, the lowest-friction version of these models is a **unique code per order**, redeemed once and bound to an account (email login or magic link). It mirrors Pearson and zyBooks and supports anti-sharing.
- Verification flows generate support load. The 시나공 thread is one example, so the redeem flow should be simple and forgiving.
- Progress tracking is proven valuable in *assigned* (teacher-driven) contexts and in habit apps. For a self-study "전자책", it would be a differentiator rather than an established expectation.
